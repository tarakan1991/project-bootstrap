# project-bootstrap

Скил для [Claude Code](https://claude.com/claude-code): разворачивает каркас документации и рабочих договорённостей проекта. Проводит короткое интервью и собирает по ответам `AGENTS.md`, `docs/` и регламенты — так, чтобы над репозиторием могли параллельно работать несколько человек и несколько ИИ-агентов.

Главный принцип: **скил не пишет документацию из головы**. То, на что ответа нет, не становится файлом-пустышкой и не выдумывается, а уходит строкой в таблицу «Дома по триггеру»: «появится X → создать Y».

## Что генерирует

| Файл | Роль |
|---|---|
| `AGENTS.md` | корневой роутер для агентов: проект, стек, глобальные правила, протокол задачи, карта доков |
| `CLAUDE.md` | однострочный импорт `@AGENTS.md` (Claude Code не читает `AGENTS.md` сам) |
| `docs/README.md` | карта документации, принципы, таблица «Дома по триггеру» |
| `docs/product.md` | продукт: пользователи, сценарии, правила предметной области, не-цели |
| `docs/architecture/` | `overview.md`, `data-model.md` — если есть содержание |
| `docs/decisions/` | ADR: шаблон + `0001`; `0002` — выбор стека, если он состоялся |
| `docs/workflow/` | `git-workflow.md`, `conventions.md`, `agents.md`, `project-workflow.md` |
| `README.md`, `env.example` | корневые заготовки |
| шаблон предложения изменений, настройки проверок | по месту репозитория, если оно известно |

Регламенты собираются **из фрагментов**, а не выбираются готовыми файлами: комбинаций ответов слишком много, чтобы держать заранее написанные варианты.

## Как работает

**Шаг 0 — репозиторий.** Скил определяет, где лежит репозиторий, по `git remote`. Репозитория нет — предлагает завести на GitHub или GitLab, проверяет наличие и авторизацию нужного инструмента, при необходимости предлагает его поставить. Интерактивный вход агент не проходит за человека, токен в чате не принимает. Отказ на любом шаге не блокирует работу.

**Три входа.** Пустой проект — интервью о продукте, затем разговор об архитектуре. Существующий код без документации — стек, структура и сложившийся процесс **вычитываются из репозитория** и показываются сводкой на подтверждение. Каркас уже есть — дозаполнение: сверка триггеров с реальностью и вопросы только по найденному.

**Стратегия ветвления** выбирается из трёх (общая ветка · ветка на задачу · ветки под окружения). Назвал своё — Git Flow, свой процесс, что угодно — скил фиксирует как есть и уточняет детали, не переучивая.

**Настройки интеграции** — схлопывать ли коммиты, удалять ли ветки, как догонять общую, имена веток, формат коммитов — показываются одним экраном с проставленными значениями: «что поправить?».

**Пять независимых осей:** ревью · задачи · тесты · проверка · выкат. Комбинируются свободно: «через ветку, но без просмотра, без трекера и без автоматики» — законная конфигурация. Опасные и противоречивые сочетания скил называет вслух один раз, с конкретной рекомендацией; человек вправе настоять — тогда решение фиксируется, а в триггеры уходит строка на пересмотр.

Каждый вариант предъявляется по одному шаблону: **что происходит и что даёт → цена → когда подходит**. Без цены человек не понимает, что выбирает.

## Константы

Переносятся в каждый проект и не обсуждаются в опросе:

- ADR для нетривиальных решений — решение фиксируется вместе с «почему»;
- один факт — один дом, плюс каскадное обновление связанных доков в одном изменении;
- **тест — контракт**: падает тест — чинится код; менять тест ради зелёной проверки нельзя;
- **разрушающее изменение схемы данных не едет вместе с выкатом, который его вводит** — откат кода не откатывает данные; перед операцией, способной потерять данные, — резервная копия;
- секреты в репозитории не хранятся; справочное генерируется из кода, а не пишется руками;
- задачи не ведутся в markdown репозитория;
- архитектура и стек не выбираются анкетой: либо приняты, либо выбираются осознанно с ADR, либо откладываются в триггер. Скил не выбирает их за человека.

## Установка

```bash
git clone https://github.com/tarakan1991/project-bootstrap.git ~/.claude/skills/project-bootstrap
```

Запуск — в корне целевого проекта: «разверни каркас документации», «настрой конституцию проекта», «bootstrap проекта».

## Структура репозитория

```
SKILL.md      # процесс: шаги, входы, оси, проверка комбинации, генерация
reference/    # развёрнутые тексты, которые скил предъявляет человеку дословно
templates/    # шаблоны файлов; дерево зеркалит корень целевого репозитория
  fragments/  # блоки, из которых собираются регламенты, и карта сборки
evals/        # сценарии тестовых прогонов скила
```

Плейсхолдеры в шаблонах: `{{...}}` подставляется из ответов интервью — после генерации `git grep -F '{{' -- '*.md'` обязан вернуть пусто.

## Проверка скила

Скил — инструкция для агента, а не код: юнит-тестами его не проверить. В `evals/` лежат сценарии — входное состояние песочницы, готовые ответы на вопросы и ожидаемый результат. Команда агенту: «прогони evals». Подробности — [evals/README.md](evals/README.md).
