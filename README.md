# project-bootstrap

Скил для [Claude Code](https://claude.com/claude-code): опросник-бутстрап нового проекта. Проводит интервью о продукте и рабочих договорённостях, а по ответам собирает каркас документации и регламентов — так, чтобы над репозиторием могли параллельно работать несколько человек и несколько ИИ-агентов.

Главный принцип: **скил не пишет документацию из головы**. На что ответа нет — не становится файлом-пустышкой и не выдумывается, а уходит строкой в таблицу «Дома по триггеру»: «появится X → создать Y».

## Что генерирует

| Файл | Роль |
|---|---|
| `AGENTS.md` | корневой роутер для агентов: проект, стек, глобальные правила, протокол задачи, карта доков |
| `CLAUDE.md` | однострочный стаб `@AGENTS.md` (Claude Code не читает `AGENTS.md` нативно) |
| `docs/README.md` | карта документации, принципы, таблица «Дома по триггеру», «куда что писать» |
| `docs/product.md` | продукт: пользователи, сценарии, бизнес-правила, не-цели |
| `docs/architecture/` | `overview.md`, `data-model.md` — только если по ответам есть содержание |
| `docs/decisions/` | ADR по Нюгарду: `template.md` + `0001` (сам факт ведения ADR); `0002` — выбор стека, если он состоялся |
| `docs/workflow/` | `git-workflow.md`, `conventions.md`, `project-workflow.md`, `agents.md` |
| `README.md`, `env.example` | корневые заготовки |
| шаблон PR/MR, CI-заготовка | по хостингу (GitHub / GitLab), если он определён |

## Как работает

**Волна 1 — продукт** (свободные вопросы): что за проект, пользователи и сценарии, участники.
**Шаг 1.5 — архитектура** (не анкета): развилка «решения уже приняты / выбираем сейчас / откладываем». Если выбираем — скил предлагает 2–3 варианта с плюсами и минусами, решение принимает человек, результат фиксируется как ADR. Ответ «выбери сам» не принимается.
**Волна 2 — воркфлоу** (варианты ответов; кнопки, если инструмент их умеет): git-режим, трекер, прод и деплой, CI, тестовая политика, хостинг репозитория.

Git-режим тянет за собой пресет процесса работы с задачами:

| Пункт | Соло-лайт | Стандарт | Команда |
|---|---|---|---|
| Старт работы | крупное — с задачей | нет задачи — нет работы | нет задачи — нет работы |
| Мерж | пуш в main для мелочи | самомерж по зелёному CI | PR-only + обязательное ревью |
| Закрывает задачу | автор после мержа | автор после проверки | постановщик после проверки |

**Режим 2 — дозаполнение.** Повторный запуск на репозитории, где каркас уже есть: скил сверяет таблицу триггеров с реальностью репо (появился код? модули без `AGENTS.md`? прод? БД?), собирает недозаполненное через `git grep -nE 'TODO|\{\{'` и спрашивает **только** по найденному — полный опрос заново не гоняет.

**Режим 3 — учебный.** Триггер: «bootstrap в учебном режиме». Волна 2 не задаётся вовсе — применяется учебный пресет (соло-лайт, без трекера, без прода, без CI, тесты отложены), а шаг 1.5 всегда уходит в ветку «отложить»: выбор стека становится отдельным упражнением после бутстрапа. В отчёте студент получает маршрут курса, а таблица «Дома по триггеру» служит картой. Репозиторий при этом полноценный — дальше проект живёт по обычным режимам 1–2.

## Константы конституции

Переносятся в каждый проект и не обсуждаются в опросе:

- задачи живут в трекере, не в markdown; ADR — для нетривиальных решений;
- архитектура, стек и хранилище — не пункты анкеты: либо уже приняты, либо выбираются осознанно с фиксацией ADR, либо откладываются в триггер. Скил не выбирает их за пользователя;
- «один факт — один дом» + каскадное обновление связанных доков в одном PR;
- `AGENTS.md` — бюджет инструкций, а не документация. Тест на строку: «уберу — агент начнёт ошибаться? Нет → режу»;
- секреты в репозитории хранить нельзя; reference (API-контракты, env) генерируется из кода, не пишется руками;
- docs-only изменения не гоняют CI;
- исходим из того, что над проектом работают несколько человек и несколько ИИ-агентов, даже если сегодня участник один.

## Установка

```bash
git clone https://github.com/tarakan1991/project-bootstrap.git ~/.claude/skills/project-bootstrap
```

Скил станет доступен в Claude Code как `project-bootstrap`. Запуск — в корне целевого проекта: «разверни каркас документации», «настрой конституцию проекта», «bootstrap проекта».

## Структура репозитория

```
SKILL.md          # инструкция скила: режимы, волны вопросов, таблица генерации, правила заполнения
templates/        # шаблоны, дерево зеркалит корень целевого репозитория
```

Плейсхолдеры в шаблонах: `{{...}}` — подставляется из ответов интервью (после генерации `git grep -F '{{' -- '*.md'` обязан вернуть пусто); `<!-- ВАРИАНТ ... -->` — выбирается один блок, остальные вместе с маркерами удаляются.

## Статус

Скил вырос из личной практики и сейчас дорабатывается в сторону универсальности. Язык шаблонов — русский; отвязка от языка и от жёстко зашитых договорённостей — направление развития.
