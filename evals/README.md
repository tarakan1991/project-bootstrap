# Evals — тестовые прогоны скила

Скил — это инструкция для агента, а не код: юнит-тестами его не проверить. Проверка здесь — **прогон в песочнице по заранее заданному сценарию с заранее известными ответами**, после которого результат сверяется с ожиданиями.

Зачем: любая правка `SKILL.md` может незаметно сломать соседний сценарий. Прогон evals ловит это до того, как скил уедет команде.

## Как прогонять

Скажи агенту: **«прогони evals»** (или «прогони eval `<имя-сценария>`»). Агент делает по каждому сценарию:

1. Создаёт песочницу — пустой каталог во временной папке сессии, `git init`, разворачивает входное состояние из блока «Дано» (файлы, коммиты, remote).
2. Запускает `project-bootstrap` в этой песочнице.
3. Отыгрывает роль пользователя: на каждый вопрос скила берёт ответ из блока «Ответы». Реального пользователя не спрашивает.
4. Вопроса в блоке нет — **доотвечает по умолчанию**, а не проваливает сценарий. Сценарий сфокусирован на одной проверке и остальное интервью намеренно не расписывает.

   | Чего нет в блоке «Ответы» | Что отвечает отыгрывающий |
   |---|---|
   | Продукт, пользователи, участники, архитектура | «пока не знаю» |
   | Экран настроек интеграции, состав проверки, раскладка набора тестов и прочие подтверждения | «без правок» |
   | Стратегия, любая из пяти осей, кто нажимает вливание | любой валидный вариант |

   Каждый доответ идёт строкой в отчёт: `доотвечено: <вопрос> → <ответ>`. Отклонением это не считается. Но если доответов набралось больше трёх — сценарий стоит дописать: он проверяет меньше, чем выглядит.
5. Сверяет результат с блоками «Ожидается» и «Не должно быть», плюс с общими инвариантами ниже.
6. Пишет строку отчёта: `сценарий — OK / отклонения (список)`.

Песочницы после прогона не удаляются до конца сессии — по ним разбираются падения.

Прогон одного сценария допустим и полезен при точечной правке: меняли блок про ревью — прогони сценарии, где ревью включено.

## Общие инварианты — проверяются во **всех** сценариях

| # | Инвариант | Как проверить |
|---|---|---|
| 1 | Плейсхолдеры вычищены | `git grep -F '{{'` пусто |
| 2 | Маркеры вариантов вырезаны | `git grep -F '<!-- ВАРИАНТ'` и `git grep -F '<!-- фрагмент'` пусто |
| 3 | Карта в `AGENTS.md` = реально созданные файлы | каждый упомянутый путь существует; каждый созданный файл упомянут |
| 4 | Состав в `docs/README.md` = реально созданные файлы | то же |
| 5 | Нет битых ссылок между доками | каждая относительная ссылка ведёт в существующий файл |
| 6 | **Нет упоминаний отключённых процессов** | `tasks=none` → нигде «упомяни задачу», «отчёт в задачу»; `check=none` → нигде «зелёный CI»; `review=none` → нигде «апрув». Таблица «Дома по триггеру» не в счёт: она по определению называет то, чего ещё нет. Прямая констатация «проверки нет, поэтому …» — тоже не протечка |
| 7 | Нет секретов | ни токенов, ни паролей, ни ключей, ни строк подключения с учётными данными; `env.example` без значений. Адреса окружений и домены — не секрет, их наличие в `environments.md` нарушением не считается |
| 8 | Нет пустышек | ни один созданный файл не состоит из одних заголовков и TODO |
| 9 | Таблица триггеров согласована | всё, что не сгенерировано по осям, присутствует строкой в «Дома по триггеру»; ни одна строка не создаёт уже созданный файл. Строка, указывающая на раздел внутри существующего файла или на шаблон-источник, устаревшей не считается — сверять надо цель создания, а не любой путь в строке |
| 10 | Язык русский | заголовки и текст сгенерированных доков |

Инвариант 6 — главный класс регрессий при переходе на оси: текст, написанный под «командный» пресет, протекает в конфигурацию, где соответствующего процесса нет.

## Что считать провалом

- Нарушен любой инвариант.
- Вариант ответа предъявлен человеку без цены или без «когда подходит» — обязателен шаблон из трёх частей: что происходит и что даёт → цена → когда подходит. Цена, размазанная по первому абзацу через «зато» и «взамен», шаблону не соответствует.
- Использован непереведённый жаргон (`squash`, `rebase`, «автодеплой», «PR») без пояснения при первом появлении.
- Скил задал вопрос по оси, которая **в сценарии задана**, — значит проигнорировал ответ; **или** не задал вопрос, ответ на который нужен для генерации и ниоткуда не выводится.

  Оси, в сценарии не указанные, берутся по предзаполнению из репозитория или дефолту — вопрос по ним отклонением не считается, как и доответ по умолчанию (пункт 4 выше). Сценарии фокусные: перечислять в каждом все шесть решений — шум, который прячет проверяемое.
- Скил задал вопрос, ответ на который у него уже есть: он лежит в блоке «Дано» или вычитывается из репозитория (вход B), либо это то, что скил выводит сам и показывает на подтверждение — состав проверки, раскладка набора тестов, раздел про вклад из чужой копии при публичном репозитории.
- Скил выбрал за пользователя то, что выбирать не должен (архитектура, стек, хранилище).
- Предохранитель не сработал там, где сценарий его ожидает.
- Сгенерирован файл, условие для которого не выполнено.
- Пакет установлен без явного согласия; репозиторий на хостинге создан без подтверждения имени, владельца и приватности.
- Скил запустил интерактивный вход (`gh auth login`, `glab auth login`) в своей сессии вместо того, чтобы отдать команду человеку.
- Скил принял токен доступа текстом в чате или записал его в файл.
- Бутстрап остановлен из-за отсутствующего инструмента, недоступного репозитория или нерешённого хостинга.
