# Место репозитория — что от него зависит

«Хостинг» — внутренний термин. **Человеку это слово не произносится**: в вопросах — «где лежит репозиторий» или прямо «GitHub или GitLab».

## Четыре зависимости

| Что зависит | GitHub | GitLab |
|---|---|---|
| Как называется предложение влить ветку | pull request | merge request |
| Где лежит шаблон описания | `.github/pull_request_template.md` | `.gitlab/merge_request_templates/Default.md` |
| Где описаны автоматические проверки | `.github/workflows/tests.yml` | `.gitlab-ci.yml` |
| Как закрывается прямая запись в главную ветку | rulesets; для приватного репозитория нужен платный план | protected branches; бесплатно, включая свой сервер |

Плюс инструмент командной строки: `gh` против `glab`.

Названия — не синонимы-жаргон, а подписи на кнопках. Регламент со словом «pull request», прочитанный человеком в GitLab, отправляет его искать кнопку, которой там нет.

## Определение по remote

| Хост | Вывод |
|---|---|
| `github.com` | GitHub |
| `gitlab` в имени хоста, включая свой сервер (`gitlab.company.ru`) | GitLab |
| прочее | «другое» — артефакты места не создаются, уходят в триггеры |

## Инструмент

| | GitHub | GitLab |
|---|---|---|
| Установка (Windows) | `winget install --id GitHub.cli` | `winget install --id glab.glab` |
| Установка (macOS/Linux) | `brew install gh` | `brew install glab` |
| Проверка | `gh --version`, `gh auth status` | `glab --version`, `glab auth status` |
| Вход | `gh auth login` | `glab auth login` (для своего сервера спросит адрес) |
| Создание репозитория | `gh repo create <имя> --private --source=. --remote=origin --push` | `glab repo create` — флаги сверить с `--help` |

**Windows:** установщик правит `PATH`, поэтому версию проверять в новом окне терминала. Новая вкладка не считается.

**Вход интерактивный** — открывает браузер и ждёт. Агент его у себя не запускает: команда отдаётся человеку, дальше ожидание подтверждения и повторная проверка статуса.

**Токен** текстом в чате не принимается, в файлы не пишется, в команды не подставляется. Единственный путь — штатный вход, кладущий токен в системное хранилище.

## Приватность

Спрашивается при создании вместе с именем и владельцем. Влияет на генерацию:

- публичный → раздел про вклад из чужой копии репозитория в `git-workflow.md`;
- приватный на GitHub → в разделе защиты ветки остаётся оговорка про платный план.

## Место неизвестно

Валидное состояние. Не создаются: шаблон предложения изменений, настройки проверок, раздел защиты ветки. Все три уходят строками в «Дома по триггеру». Терминология в доках — нейтральная либо помеченная как уточняемая.
