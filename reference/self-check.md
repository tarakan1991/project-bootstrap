# Самопроверка после генерации

Обязательный шаг, не пропускать. Нарушение — чинить до отчёта человеку, а не упоминать в отчёте как замечание.

## 1. Плейсхолдеры и маркеры

```bash
git grep -F '{{' -- '*.md'
git grep -F '<!-- ВАРИАНТ' -- '*.md'
git grep -F '<!-- фрагмент' -- '*.md'
```

Все три — пусто. Осталось хоть что-то → файл собран не до конца.

## 2. Карты совпадают с реальностью

- Каждый путь, упомянутый в `AGENTS.md` и в разделе «Состав docs/» файла `docs/README.md`, существует.
- Каждый созданный файл упомянут в соответствующей карте.
- Ни одной ссылки на несуществующий файл во всех сгенерированных доках.

**Исключение — таблица «Дома по триггеру».** Она по определению называет файлы, которых ещё нет: это её содержание, а не битые ссылки. Проверять её надо на другое — что там не осталось строки про уже созданный файл.

## 3. Нет упоминаний отключённых процессов

Главный класс ошибок: текст, написанный под полный набор, протекает в конфигурацию, где процесса нет.

| Если выбрано | В доках не должно встречаться |
|---|---|
| `tasks=none` | «упомяни задачу», «отчёт в задачу», «номер задачи в имени ветки», ссылки на трекер |
| `check=none` | «зелёная проверка», «дождись автоматики», требование зелёного статуса перед вливанием |
| `review=none` | «апрув», «согласие другого человека», «ревьюер» |
| `strategy=trunk` | «предложение изменений», «pull request», «merge request», защита ветки |
| `prod=none` | «выкат», «прод», «откат на проде», окружения |
| `tests=deferred` | требование тестов в чек-листе перед вливанием |

Проверяется поиском по сгенерированным файлам, а не по памяти.

**Исключение — константы.** Правила «тест — контракт» и «разрушающее изменение схемы не едет вместе с вводящим его изменением» кладутся всегда и упоминают тесты и данные независимо от осей. Они не считаются протечкой: тесты и миграции появятся раньше, чем кто-нибудь вспомнит про эти правила. Формулировки в них нейтральны — «чтобы проверка прошла», «изменение», а не «зелёный CI» и «выкат»; если в собранном файле стоит иначе, это ошибка сборки.

## 4. Настройки интеграции согласованы с текстом

Человек правил значения на экране настроек → в доках нет остатков прежних:

- убрано схлопывание → нет ни «схлопнуть в один коммит», ни `git branch -D` в шпаргалке (при схлопывании ветка не видна как влитая, поэтому нужен `-D`; без схлопывания — не нужен);
- ветки не удаляются → нет шага удаления ветки и чистки локальных;
- имена веток без номера задачи → нигде не `42-описание`.

## 5. Место репозитория

| Выбрано | Проверить |
|---|---|
| GitHub | нет «merge request», нет `.gitlab/`, нет `.gitlab-ci.yml`; защита ветки — вариант GitHub |
| GitLab | нет «pull request», нет `.github/`, нет `gh api`; защита ветки — вариант GitLab |
| Неизвестно | нет ни `.github/`, ни `.gitlab/`; нет утверждений про конкретное место; строки ушли в триггеры |

## 6. Таблица триггеров

- Каждое несгенерированное по условиям — присутствует строкой в «Дома по триггеру».
- Каждая строка актуальна: нет триггера на то, что уже создано.
- Сработавшие предупреждения шага 5 оставили строку на пересмотр, если человек настоял на своём.

## 7. Содержание

- Ни один созданный файл не состоит из одних заголовков и TODO.
- Нет выдуманного содержания там, где человек ответил «пока не знаю».
- Нет секретов: ни токенов, ни ключей, ни адресов серверов; `env.example` — имена переменных без значений.
- Правила-константы на месте: тест-контракт и разделение миграций есть в `conventions.md` и `agents.md` **независимо** от выбранных осей.

## 8. Язык

Русский во всех сгенерированных доках. Английские имена — только там, где они являются именами команд, файлов или подписями в интерфейсе.
