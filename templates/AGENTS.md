## Протокол задачи

1. Прочитай задачу в трекере. Критерий готовности неясен → уточни ДО начала работы.
2. Сверься с `docs/product.md` (сценарии, бизнес-правила) и `docs/decisions/` — план не противоречит принятым решениям.
3. Ветка и коммиты — по `docs/workflow/git-workflow.md`.
4. Работаешь в модуле — прочти его `<модуль>/AGENTS.md`; файла нет → создай по шаблону из `docs/workflow/agents.md` в том же PR.
5. Инварианты, конвенции и тестовая политика — `docs/workflow/conventions.md`.
6. Перед PR: полная проверка одной командой (`conventions.md`) + каскадное обновление доков (`docs/workflow/agents.md`).
7. PR по шаблону; отчёт в задачу по шаблону из `docs/workflow/project-workflow.md`.
8. Закрытие задачи — {{кто и когда, одной строкой из пресета}}.
