# Документация {{PROJECT_NAME}} — карта

Навигация по `docs/`. Ищешь конкретный документ — таблица «Куда что писать» внизу решает в одной строке.

## Принципы

1. **Git — механизм синхронизации.** Доки живут в репо с кодом — общий контекст для людей и ИИ-агентов.
2. **Один факт — один дом.** Любой факт записан ровно в одном месте; остальные — ссылка, не копия. Каскадное обновление при правках — `workflow/agents.md`.
3. **Разделение по типу:** операционка «как работать ЗДЕСЬ» → `AGENTS.md` рядом с кодом (короткие, императивные); нарратив «как устроено / почему» → `docs/`; задачи и планы → трекер (не markdown).
4. **Пустышек нет — дома рождаются по триггерам.** Файл создаётся, когда для него есть содержание. Что и когда создавать — таблица «Дома по триггеру» ниже.
5. **Markdown не держит todo-списков.** Это дрейф между разработчиками.
6. **AGENTS.md — бюджет инструкций, а не документация.** Каждая строка стоит токенов и внимания модели. Тест на строку: «уберу — агент начнёт ошибаться? Нет → режу».
7. **Reference генерируется из кода, не пишется руками:** API-контракты → из OpenAPI; env-переменные → `env.example` как единственный источник.

## Состав docs/ (сейчас)

```

├── README.md          # этот файл
├── product.md         # продукт: пользователи, сценарии, бизнес-правила, не-цели
├── architecture/      # как устроено СЕЙЧАС{{: перечислить созданное — overview.md, data-model.md}}
```

Рядом с кодом: корневой `AGENTS.md` (роутер) + `CLAUDE.md` (стаб `@AGENTS.md`, Claude Code не читает AGENTS.md нативно) + модульные `<модуль>/AGENTS.md` (по триггеру).

## Дома по триггеру

Сработал триггер → создай дом **в том же PR**, что и вызвавшее его изменение, и перенеси строку из этой таблицы в «Состав». Наперёд содержание не выдумываем.

| Триггер | Создать |
|---|---|
| Первый код нового модуля | `<модуль>/AGENTS.md` по шаблону из `workflow/agents.md` |
| Спроектировали систему / первый код | `docs/architecture/overview.md` — компоненты и связи |
| Выбрали БД / первая модель данных | `docs/architecture/data-model.md` — хранилище, миграции, источник схемы для агентов |
| Первый HTTP-endpoint | `docs/architecture/api.md` — генерируется из OpenAPI, руками не пишется |
| Первый UI-код | `docs/design.md` — дизайн-система, бренд, UI-принципы |
| Первый неоднозначный термин домена | `docs/glossary.md` — «**Термин** — определение», по строке |
| Первое исследование | `docs/research/` + README: дистиллированные выводы сюда, сырьё со скринами — в трекер/обсуждения, здесь ссылка + вывод |
| Появился прод / первый деплой | `docs/workflow/environments.md` (окружения, где живут секреты) + `docs/workflow/runbooks.md` (бэкап/восстановление, деплой/откат; формат: когда применять → шаги → как проверить → как откатить) |
<!-- строки ниже включать только если актуальны по ответам опроса: -->
| Появился первый код (CI решили вести) | CI-заготовка (`.github/workflows/tests.yml` / `.gitlab-ci.yml`) — прогон единой команды проверки; docs-only изменения пайплайн не гоняют |
| Выбрали хостинг репозитория (был «не решён») | шаблон PR/MR, CI-заготовка, раздел «Защита ветки» в `workflow/git-workflow.md` |
| Появился прод (тест-политика «отложено») | пересмотреть политику тестов в `workflow/conventions.md` |
| Второй активный разработчик (режим соло-лайт) | перегенерировать `workflow/git-workflow.md` на режим «стандарт» |

## Куда что писать

| Хочу записать… | Куда |
|---|---|
| Команду запуска/теста модуля, грабли модуля | модульный `AGENTS.md` |
| Глобальное правило (коммиты, секреты, DoD) | корневой `AGENTS.md` |
| Сценарий пользователя, бизнес-правило, не-цель | `docs/product.md` |
| Как устроен модуль сейчас | `docs/architecture/…` (дом по триггеру) |
| Почему выбрали X, а не Y | новый ADR в `docs/decisions/` |
| Договорённость по процессу / workflow | `docs/workflow/` |
| Конвенцию кода / инвариант | `docs/workflow/conventions.md` |
| Баг / фичу / техдолг / задачу | трекер (см. `workflow/project-workflow.md`) |
| Личную заметку / sandbox | `CLAUDE.local.md` (gitignore) или `scratch/` |

## Правила, чтобы доки не сгнили (Definition of Done)

1. PR, меняющий архитектуру, **в том же PR** обновляет нужный `docs/architecture/*`.
2. Нетривиальное/спорное решение → новый ADR.
3. Задачи — только в трекере. В markdown todo-списков нет.
4. Один факт — один дом. Нашёл дубль — оставь источник, остальное замени ссылкой.
5. Модульный `AGENTS.md` > 80 строк → внутрь заполз нарратив, выноси в `docs/architecture/`.
6. Сработал триггер из таблицы — дом создаётся в том же PR.
7. **Каскадное обновление** перед коммитом — пары документов, которые могут разойтись, проверяются `git grep` (см. `workflow/agents.md`).
