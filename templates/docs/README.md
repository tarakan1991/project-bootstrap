# Документация {{PROJECT_NAME}} — карта

Навигация по `docs/`. Ищешь конкретный документ — таблица «Куда что писать» внизу решает в одной строке.

## Принципы

1. **Git — механизм синхронизации.** Доки живут в репозитории с кодом — общий контекст для людей и ИИ-агентов.
2. **Один факт — один дом.** Любой факт записан ровно в одном месте; остальные — ссылка, не копия. Каскадное обновление при правках — `workflow/agents.md`.
3. **Разделение по типу:** операционка «как работать ЗДЕСЬ» → `AGENTS.md` рядом с кодом (короткие, императивные); нарратив «как устроено и почему» → `docs/`; задачи и планы → {{трекер / «пока нигде, но не в markdown»}}.
4. **Пустышек нет — дома рождаются по триггерам.** Файл создаётся, когда для него есть содержание. Что и когда создавать — таблица ниже.
5. **Markdown не держит списков задач.** Это расхождение между участниками.
6. **AGENTS.md — бюджет инструкций, а не документация.** Каждая строка стоит токенов и внимания модели. Тест на строку: «уберу — агент начнёт ошибаться? Нет → режу».
7. **Справочное генерируется из кода, не пишется руками:** контракты интерфейсов — из описания API; переменные окружения — `env.example` как единственный источник.

## Правила, чтобы доки не сгнили

1. Изменение, меняющее архитектуру, **в том же изменении** обновляет нужный `docs/architecture/*`.
2. Нетривиальное или спорное решение → новый ADR.
3. Списков задач в markdown нет.
4. Один факт — один дом. Нашёл дубль — оставь источник, остальное замени ссылкой.
5. В модульном `AGENTS.md` появились абзацы про то, **как устроено** и **почему так вышло**, → это нарратив, выноси в `docs/architecture/` и ADR. Длина сама по себе не признак: двадцать настоящих граблей — это двадцать нужных строк.
6. Сработал триггер из таблицы — дом создаётся в том же изменении.
7. **Каскадное обновление** перед коммитом: пары документов, которые могут разойтись, проверяются поиском (см. `workflow/agents.md`).
