# 0001. Ведём Architecture Decision Records

- **Дата:** {{DATE}}
- **Статус:** accepted

## Контекст
Нужен лог архитектурных решений с ответом на вопрос «почему так, а не иначе» —
тот, который нельзя вывести из кода. Без него знание теряется, а ИИ-агенты и новый
разработчик повторяют уже отвергнутые варианты.

## Решение
Ведём ADR в docs/decisions/ по шаблону Майкла Нюгарда (template.md).
Нумерация монотонная, номера не переиспользуются. Файлы append-only:
принятый ADR не редактируется (кроме опечаток/ссылки на superseder).
Решение устарело → новый ADR со статусом «superseded by 00YY», старый помечается «superseded».

## Последствия
- Истина по архитектуре — цепочка ADR, а не последний файл.
- Нетривиальное/спорное решение фиксируется в том же изменении (часть Definition of Done).
- Агент перед изменением архитектуры обязан свериться с docs/decisions/.
