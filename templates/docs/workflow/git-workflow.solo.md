# Рабочий процесс: git (режим «соло-лайт»)

> Режим для 1–2 человек без взаимного ревью: минимум церемоний, но несколько жёстких правил.
> Конвенции кода и инварианты → `conventions.md`. Задачи → `project-workflow.md`.

## Что означает `main`

<!-- ВАРИАНТ A — мерж/пуш в main запускает автодеплой на прод. Оставить этот блок, удалить вариант B. -->
Пуш в `main` запускает автодеплой на прод. **Каждый пуш = выкат.** Поэтому в `main` попадает только проверенное состояние: прогнал полную проверку (`conventions.md`) — потом пушь.

<!-- ВАРИАНТ B — автодеплоя нет (или прода пока нет). Оставить этот блок, удалить вариант A. -->
`main` всегда в рабочем состоянии: собирается, проверка проходит. Деплой — отдельное осознанное действие.

## Правила

- **Мелкое** (правка, докфикс, небольшая фича за один присест) — можно коммитить прямо в `main`.
- **Крупное или рискованное** (работа на несколько дней, миграции БД, рефакторинг) — ветка `{номер-задачи}-описание` + PR. PR даёт CI, историю изменений и точку отката.
- Коммиты: русский язык, `тип: глагол + что делает` (`feat` / `fix` / `chore` / `docs` / `refactor`), без точки в конце, ≤72 символов.
- В ветках — `rebase` на `origin/main`, не `merge`. Пуш rebase-нутой ветки — только `git push --force-with-lease`, **никогда** `--force`.
- **Откат — через `git revert`**, историю после пуша не переписываем.
- Времянки и отладочные скрипты → `scratch/`, логи → `logs/` (см. `conventions.md`), не в корень и не в модули.
- Перед пушем в `main` — полная проверка одной командой (`conventions.md`).

## Жизненный цикл ветки (для крупного)

```bash
git checkout main && git pull
git checkout -b 42-краткое-описание
# ... работа, коммиты ...
git fetch origin && git rebase origin/main
git push --force-with-lease origin 42-краткое-описание
# PR → проверка → squash-merge
git checkout main && git pull
git branch -D 42-краткое-описание   # squash-мерж не виден как merge → -D, не -d
```

## Когда перерастём

Появился второй активный разработчик или первые пользователи на проде → переходим на режим «стандарт» (PR-only, самомерж по зелёному CI): триггер зафиксирован в таблице «Дома по триггеру» (`docs/README.md`) — перегенерировать этот регламент.
