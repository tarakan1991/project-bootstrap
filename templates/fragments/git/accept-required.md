## Приём изменений

Изменение вливается **после согласия другого участника**.

- **Автор не вливает без ответа.** Смотрящий не соглашается, пока не обновлены доки, которых требует изменение (правило из `docs/README.md`).
- **Смотрящий проверяет по критерию готовности**{{ (`project-workflow.md`)}}: изменение делает заявленное целиком; тесты соответствуют политике; затронута архитектура → обновлён `docs/architecture/*`; нетривиальное решение → есть ADR.
  <!-- фрагмент: ссылка на project-workflow.md — только при tasks ≠ none, иначе файла не существует -->

- **Предложение маленькое.** Чем крупнее изменение, тем поверхностнее его смотрят: на 800 строк отвечают «выглядит нормально». Большую задачу режем на несколько предложений — цепочкой, если инструмент это умеет.
- **Ответ — в течение рабочего дня.** Дольше — автор переключается на другое, и возврат стоит дороже самого просмотра.
- **Прямая запись в `main` не используется.**
